# T07 The baseline and the race bake-off

- **Kind**: slice
- **Issue**: #8 · **Branch**: `task/T07-bakeoff` · **Merge after**: T04, T06
- **Owns**: `src/measure/bakeoff.test.ts` (or a `tools/` runner if play-length
  runs need to sit outside the suite), `docs/runs/<date>-bakeoff/`.
- **Scope**: The fork's first measured statement: with warrior birth and the
  restart loop in place, run the headless harness over the four candidate races
  (Half-Troll, Dunadan, High-Elf, Dwarf) × a fixed seed set, same plan and
  decision budget per run, and write the session to `docs/runs/` with the
  curated table. The comparison is the point: median and best `maxDepth`,
  deaths in town versus the dungeon, character level reached, and the command
  census per race. End with an owner decision on the default `raceChoice`
  (issue comment, options = the four candidates with their numbers). No
  decision-code changes in this task - it measures the fork as it stands.
- **Done when**:
  1. `docs/runs/<date>-bakeoff/` holds `runs.json` (harness-written) and
     `README.md` (the table, per-race aggregates, and what changed since
     `2026-11-02-import`).
  2. Every run in it is the planned Warrior build (asserted at boot by the
     harness, recorded per run).
  3. The decision issue carries the four options with their numbers and a
     recommendation; the suite stays green (`pnpm verify`; bake-off runs
     themselves may be a `tools/` invocation, not a suite test, if they would
     run long - say which and why in the README).
- **Hazards**: comparing races across different seeds or budgets - the sweep
  must cross them (same seeds for every race) or the table lies; and letting a
  lucky outlier pick the default - the recommendation argues from medians, and
  the owner decides.
