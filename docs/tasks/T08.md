# T08 Milestone 0.1.0: the warrior always comes back

- **Kind**: infrastructure
- **Issue**: #9 · **Branch**: directly on `main` (metadata) · **Merge after**: T02–T07
- **Owns**: `CHANGELOG.md`, `manifest.json`/`package.json` versions, the
  milestone issue.
- **Scope**: Close the first milestone. Finalize the 0.1.0 changelog entry
  (what shipped: warrior birth, restart loop, run records, the bake-off's
  default race), bump nothing that T01 did not already set unless a task
  changed the surface. Open the milestone issue with: proposed tag `v0.1.0`,
  the candidate SHA, the merged tasks, the checks run on the candidate, the
  claims to verify (each with `file:line`), and the owner decisions that are
  not defects (default race from T07; divergence policy). The owner launches
  the review (`docs/process.md` §4); findings land as issues; AGREE (or an
  owner tag without review, noted) tags the exact SHA.
- **Done when**:
  1. The milestone issue exists with candidate SHA, claims, and decisions.
  2. `pnpm verify` is green on the candidate (play-harness skip rule aside).
  3. `v0.1.0` exists on exactly the reviewed SHA and `node tools/build.mjs
     --check` passes at the tag.
- **Hazards**: tagging a SHA that is not the candidate (fixes after the
  candidate move it; the issue must name the new SHA), and claims that restate
  the tasks instead of naming code a reviewer can check.
